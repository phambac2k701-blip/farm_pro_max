## 1. Purpose

This document defines the complete structural event set for the currently approved Chapter 0–3 macro before gameplay-event implementation begins.

It is intentionally more concrete than the chapter macro, but it does not invent final important-NPC identities, exact lived-experience details, final dialogue, official UET branding, major relationship arcs, or Chapter 4+ content.

Each event has a stable ID and production role so implementation can proceed without creating a different story structure inside code.

## 2. Global event rules

- one continuous student life, not anthology episodes
- ordinary actions may carry gameplay value
- most choices are local micro-branches and reconverge
- persistent facts are rare and only kept when later chapters genuinely need them
- foregrounded details should have a later reason/payoff
- study creates context; it does not dominate the game
- humor comes from believable timing, friction, routine and social awkwardness
- no mystery/uncanny layer in Ch0–Ch3 unless later explicitly approved
- Chapter 4+ remains locked

## 7. Cross-chapter continuity requirements

The following continuity threads must be resolved before final event implementation:

1. **Navigation confidence** — CH0 unfamiliar-city friction should contrast with later routine movement.
2. **Recurring contact channel** — the first useful social/group-information channel from CH0 should have a believable successor/reuse in Ch2–Ch3.
3. **Hòa Lạc carry-forward** — at least one person, habit, joke, object memory or routine from Ch1 must recur later once the user approves which one.
4. **GD4 familiarity** — CH2 establishes spatial/social anchors; CH3 must reuse them with changed familiarity.
5. **Phone/group information** — phone interactions must evolve from practical information into ordinary social coordination, not become a separate game.
6. **Ordinary-object callbacks** — selected seat/bag/charger/paper/drink-scale details may recur when they have a clear payoff.
7. **Vibe coding** — only appears visibly in Ch3; do not retroactively force it into Ch0–Ch2 unless the user later supplies such material.
