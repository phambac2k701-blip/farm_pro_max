# NARRATIVE EVENT STYLE V2 — UETốt

Status: **USER-APPROVED NARRATIVE / EVENT DIRECTION**
Date: 2026-10-02
Canon owner: **User / primary writer**

## 1. Core tone

The game should build memorable scenes from ordinary student life.

Baseline event tone:
- grounded and recognizable
- mundane situations are allowed to carry gameplay
- humor may be absurd / "vô tri" but must emerge from the situation
- humor should feel current and trend-aware rather than like generic scripted jokes
- the target internet-culture window for Chapter 0 presentation is roughly **June–December 2025**
- humor may include deliberate anti-humor, stale-joke callbacks, brainrot/repetition, or remix culture when the context makes the repetition itself funny
- a scene may contain a small twist, reversal, surprise, or brief tension spike
- "twist" does not imply horror, mystery, supernatural content, or a major plot reveal

The game should avoid narrator-heavy comedy. Whenever possible, humor should come from:
- player participation
- NPC timing
- awkward silence
- an option chosen by the player
- a believable misunderstanding
- expectation vs reality
- an object/environment reaction
- a plan going slightly wrong
- a callback to an earlier ordinary detail

## 2. First-person presentation

POV does not mean continuous internal narration.

Prefer:
- visible action
- environmental information
- short dialogue
- player-controlled looking/movement
- timed reactions
- optional internal lines only when they add something the scene cannot already show

Avoid:
- long explanatory voice-over
- narrator jokes that explain why a situation is funny
- prose-style paragraphs replacing playable scene behavior

## 3. Small-choice model

Most ordinary options are **local micro-branches**, not permanent routes.

A small choice may be:
- socially awkward
- inefficient
- based on incomplete information
- locally "wrong"
- funny in consequence
- temporarily off the intended path

But it should normally:
1. produce a distinct reaction/consequence;
2. allow the player to experience the result;
3. use an authored in-world reason to redirect/reconverge;
4. return to the main route without a bad ending.

The reconvergence must feel caused by the world, not by an invisible designer reset.

Examples of valid reconvergence causes:
- the person the player followed was also wrong and turns back;
- a room/office is closed;
- a message corrects the information;
- an NPC redirects the player;
- the object/action fails in a believable way;
- timing/schedule forces everyone back to the same destination;
- the player discovers the missing context and self-corrects.

## 4. Major-choice model

Major choices are different from ordinary micro-choices.

A major choice may:
- create a persistent fact;
- alter a relationship;
- change later events;
- open/close a long-term route;
- eventually contribute to a different ending.

These choices must have real narrative weight and user approval.

Do not define final endings yet. Ending design is deferred.

## 5. Humor direction

Desired humor:
- ordinary Vietnamese/student situations
- absurd/deadpan "vô tri" timing
- contemporary internet/TikTok-aware rhythm when appropriate
- visual or interaction-based joke structure
- jokes that can survive even if dialogue is short
- callbacks that get funnier because the player remembers an earlier event

Avoid:
- random meme insertion
- copying a trend without connection to character/context
- every NPC speaking like a TikTok caption
- forced slang in every line
- narrator explaining the joke
- comedy that breaks the grounded student-life world

Because trends age quickly, concrete trend references should be researched at the time of writing and treated as replaceable presentation details, not core canon.

## 6. Creative expansion rule

User-supplied events/interactions are a **creative spine, not a whitelist**.

A narrative worker may propose:
- small interruptions;
- side interactions;
- environmental gags;
- extra local options;
- a short detour;
- a callback;
- an NPC reaction;
- a visual punchline;
- a micro-event that crosses through an existing event.

The added material must:
- remain causally connected to the current scene;
- respect the approved chapter direction;
- not create important recurring canon without approval;
- not manufacture a major new plot simply to add content;
- preserve provenance as AI proposal / research-based proposal until approved.

The worker should improve and expand the user's idea when it finds a genuinely stronger playable expression. It should not mechanically transcribe the user's first-pass interaction list.

## 7. Internet-culture / trend humor rule

For Chapter 0 and other scenes set around the same period, research internet culture from roughly **mid-2025 through late-2025**.

Research should include more than "funny memes". Look for:
- phrases or numbers that became funny through repetition;
- brainrot / absurd formats;
- anti-jokes;
- intentionally outdated or "corny" expressions whose staleness becomes the joke;
- serious or neutral public events that netizens transformed into remix/meme formats;
- comment-section phrasing;
- reaction formats;
- repeated catchphrases;
- formats whose humor depends on overuse.

Examples mentioned by the user as **reference patterns, not mandatory inclusions**:
- "36";
- "67";
- deliberately stale internet language such as "bó tay chấm com" / "ảo tung chảo";
- repetition spam where repeating the same token is itself the gag.

Do not judge a meme only by whether the original subject is comedic. Analyze how the online community repurposed it.

However:
- verify the time period before using a concrete reference;
- prefer format/rhythm over copying a real person's controversy verbatim;
- do not turn unverified allegations about real people into game facts;
- do not target private people or victims;
- a reference must still fit the scene and character voice.

"Meme spam" is not automatically a defect. Repetition is valid when escalation, timing, character behavior, or context makes the repetition the punchline. If repetition adds nothing, cut it.

## 8. Twist / surprise rule

A small event may include:
- expectation reversal
- information revealed late
- a person/object behaving differently from what the player assumed
- a short moment of tension immediately recontextualized
- a choice that seems sensible but produces a funny/unexpected consequence

A twist should:
- be prepared by visible information;
- make sense after the reveal;
- not require fake information from the game;
- not automatically become permanent story lore.

## 9. Event categories

Do not call every routine action a story event.

Use these categories:

### Routine system
Reusable gameplay:
- choose seat
- sit/stand
- check phone
- enter class
- navigate
- order/drink
- wait
- use ordinary objects

### Ambient beat
Optional small world moment with little/no progression.

### Character beat
Changes understanding/relationship/chemistry between people.

### Story event
Specific occurrence with a before/after narrative state.

### Major event
Chapter-level turning point or choice with durable consequences.

## 10. Two-worker narrative production model

Maximum narrative workers active at once: **2**, plus coordinator.

### Worker A — Event Architect / Branch Designer

Input:
- user-supplied raw memories/material
- approved chapter macro
- approved character facts
- map/runtime constraints
- existing continuity ledger

Responsibilities:
- identify candidate events from user material
- distinguish routine vs ambient vs character vs story vs major event
- define event purpose
- define entry/exit state
- design player verbs/interactions
- design options
- design local consequences
- design authored reconvergence reasons
- identify setup/payoff/callback
- identify which details still require user approval
- never finalize dialogue

Output:
- event graph/spec
- option graph
- continuity/state implications
- approval questions/placeholders

### Worker B — Scene / Interaction Writer

Input:
- an approved/selected event graph from Worker A
- user-supplied lived detail
- current character states
- current trend/humor references when explicitly researched/allowed
- map/interaction capabilities

Responsibilities:
- turn the approved event graph into playable scene beats
- write concise dialogue
- write short internal thoughts only when useful
- define reaction timing / silence / visual comedy
- attach lines/reactions to each option
- define object/NPC interaction text
- preserve all branch and reconvergence constraints
- do not alter event causality or create new canon

Output:
- scene script
- dialogue by node/option
- interaction/reaction beats
- implementation-ready presentation notes

## 11. Coordinator responsibilities

The coordinator:
- receives raw material from the user
- keeps raw memory separate from interpretation/canon
- assigns Worker A and Worker B
- prevents Worker B from rewriting Worker A's approved structure
- checks continuity across chapters
- checks gameplay repetition
- checks source-of-truth compliance
- asks the user only for canon decisions that genuinely require the user's lived experience/creative judgment

The user remains final authority for:
- what actually happened / what personal material is used
- important character identity
- major relationships
- major story turns
- persistent route choices
- endings
- final canon

## 12. Chapter 0 current rule

Chapter 0 does not need final ending/route design.

Focus on:
- ordinary entry-to-university situations
- first Hanoi/UET impressions
- small playable options
- local funny mistakes/detours
- authored reconvergence
- small twists/reversals
- establishing recurring details that may later be reused

Do not invent final ending logic from Chapter 0 material.
